# Issue #5：使用者選取的場景與材質載入

狀態：**本機已驗證；尚未提交、推送或發布公開網站。** 使用者已確認規格並要求開工（2026-09-23）。追蹤：[GitHub Issue #5](https://github.com/wicanr2/focoria/issues/5)。

## 目標與已知事實

Focoria 是通用的瀏覽器三維模型檢視器。使用者選取的檔案應決定可切換的場景，介面不應預設只有沙崙模型。載入按鈕下方要說明實際支援格式，以及材質何時會自動出現、何時必須一起選取外部檔案。

目前程式使用檔案選擇器或拖放取得本機檔案，並在瀏覽器記憶體中解析；它只載入同批檔案中的第一個主模型。現有場景清單則來自部署端的 `manifest.json`，與使用者選取的檔案無關。一般材質由 Three.js 載入器處理；另有沙崙 GLB 與特定 USDA 材質舞台的專用覆蓋流程。這些是現況，不是新需求已完成的證明。

## 預期操作

1. 初次開啟時不顯示預設沙崙場景；場景清單呈現空狀態。使用者可以按「載入模型」或拖放檔案。
2. 一次選取多個可直接開啟的模型時，清單只列出這批檔案中的主模型；貼圖、`.bin` 等相依檔不成為場景選項。預設載入第一個模型，切換清單項目時載入對應模型，並保留同批相依檔供解析。
3. 沒有主模型時顯示可理解的提示，不把貼圖或 `.bin` 冒充成場景。檔案載入失敗時保留明確錯誤，不顯示空場景為成功。
4. 使用者再次選取含主模型的新批次時，新模型與相依檔取代舊批次；清單同步重建，不累加舊場景。若新選取沒有主模型，顯示提示並保留目前可用的場景，不用無效輸入清空它。
5. 選檔、解析與場景切換均在瀏覽器內完成，不因本規格增加伺服器上傳、帳號或持久儲存。私有模型與貼圖不得加入公開儲存庫。

## 載入按鈕下方的說明

說明要短，但不能超出真正支援範圍。建議文案：

> 可開啟 GLB、glTF、FBX、自包含的 ASCII USD／USDA，以及相容的 USDZ。`.blend` 與二進位 USDC 尚未支援。
>
> 模型內的材質會自動載入。外部貼圖或 `.bin` 請與主模型同次選取；瀏覽器無法自動讀取未選取的本機檔案。

`.usd` 只有在內容為目前載入器支援的 ASCII USDA 時才可直接開啟；帶有外部 `references`、`payload` 或 `subLayers` 的 OpenUSD 組合舞台不在此承諾內。相容 USDZ 的解析仍受目前 Three.js 載入器能力限制。直接開啟 `.blend` 由 [Issue #2](https://github.com/wicanr2/focoria/issues/2) 追蹤；不能為了讓文字看起來完整而先寫成已支援。

## 材質行為與通用性

- GLB、glTF、FBX 等主模型若含載入器可讀的材質，載入時直接顯示；有外部相依檔時，只使用使用者同批選取且能明確對應的檔案。
- 材質狀態須區分「貼圖已載入」、「只有純色材質」、「缺少外部貼圖」、「解析失敗」，不能一律顯示「材質自動載入」或把色彩備援當成完整貼圖。
- 現有沙崙 USDA 覆蓋屬相容性功能，不能成為通用載入的前置條件，也不能因同批出現任意 USDA，就把它套到無關 GLB。多模型與多 USDA 的配對規則在實作前須明確驗證；無法唯一配對時不自動覆蓋。
- 介面不寫入任何沙崙專屬檔名、樓層或絕對路徑。部署端的靜態模型清單與本次選取的場景清單不可混為一談；本規格的主要清單以使用者選檔為準。

## 驗收與非目標

以非沙崙範例測試：初始空清單、單一 GLB、多個主模型切換、glTF 加 `.bin` 與外部貼圖、缺少貼圖、只選相依檔、再次選檔，以及不支援格式。檢查清單項目、模型幾何、材質狀態與錯誤訊息；至少有一次從真正的載入按鈕開啟檔案選擇器的瀏覽器操作驗證。建置與測試須在受限 Docker 容器內進行，不把私有模型放入公開測試資料。

本 Issue 不實作 `.blend` 解析、完整 OpenUSD 組合、模型上傳伺服器或 GitHub Pages 發布。更名後的標題、套件與啟動入口另由 [Issue #1](https://github.com/wicanr2/focoria/issues/1) 追蹤；本機重部署需等規格確認及相應實作驗證後進行。
